# Packet P4-5b — /supervise dispatch pattern for harnesses that auto-background long commands

Finding (Chief, 2026-09-12): Claude Code's Bash tool moves any command running longer than
120 s to the background and returns; a headless `-p` session then ends its turn waiting for a
notification that never comes, and the child dies with it. This killed three Phase 3/4
launches. It is a harness property, not disobedience.

Change (router, `templates/shims/supervise.md.tmpl` + parity tests + reinstall):
replace the "foreground" instruction with the proven dispatch pattern:
1. Start `lee-llm-router run …` detached: `setsid nohup bash -c "cd <repo> && lee-llm-router
   run … > <log> 2>&1; echo done=\$? >> <log>" < /dev/null &`.
2. Poll in bounded foreground loops of at most 90 s each: `timeout 90 bash -c "until grep -q
   '^done=' <log>; do sleep 10; done"`; repeat the poll call until it succeeds; never a single
   call longer than 90 s; never a background tool; never end the turn while the log lacks
   `done=`.
3. Then read the attempt record `run` printed (or `census`/the ledger tail) before deciding.
Same pattern for reviews. Keep the rule "never end your turn while anything you started is
running". Class `impl/deterministic/none/xs/markdown`. Independent review. Commit
`feat(staffing P4): supervise dispatch pattern for auto-backgrounding harnesses`.
