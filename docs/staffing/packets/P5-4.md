## What to build

### `scripts/refresh_pricing_snapshot.sh`

Usage: `refresh_pricing_snapshot.sh [--date YYYY-MM-DD] [--out-dir DIR] [--dry-run] [--zen-commit SHA]`

1. **OpenRouter**: `curl -fsSL https://openrouter.ai/api/v1/models` → validate it is a JSON
   object with a non-empty `data` list (use `python3 -c` for the check; no jq dependency) →
   write `openrouter-<date>.json` and `openrouter-<date>.json.sha256` (sha256sum format,
   basename only) atomically.
2. **OpenCode Zen docs table**: resolve the pinned commit: `--zen-commit SHA` if given, else the
   latest commit touching the file via
   `https://api.github.com/repos/sst/opencode/commits?path=packages/web/src/content/docs/zen.mdx&per_page=1`
   (extract `.[0].sha` with python3). Fetch
   `https://raw.githubusercontent.com/sst/opencode/<sha>/packages/web/src/content/docs/zen.mdx`
   (pinned commit, never `dev`) → require it to be non-empty and to contain the string
   `OpenCode Zen` → write `opencode-zen-<date>.mdx`, its `.sha256`, and
   `opencode-zen-<date>.mdx.source` containing two lines: `commit=<sha>` and `url=<raw url>`.
3. If a target file for `<date>` already exists, refuse (exit 4) unless `--dry-run`; never overwrite.
4. On success print, to stdout: each written path with its sha256; then a **proposed** terms
   repoint block — the exact `config/staffing/terms.yaml` / `channels.yaml` lines that would
   change from the currently referenced snapshot names (grep them out of the YAML; do not
   guess) to the new ones, headed `PROPOSED (not applied) — apply through a reviewed commit:`;
   then a `PROPOSED CRON (not installed):` line `15 06 * * 1 cd /home/lee/projects/lee-llm-router && scripts/refresh_pricing_snapshot.sh >> ~/.local/state/lee-llm-router/pricing-refresh.log 2>&1`
   (weekly Monday 06:15 local; the schedule owner installs it, not this script).
5. `--dry-run`: perform the fetches to a temp dir, print what would be written and the two
   PROPOSED blocks, write nothing under `--out-dir`.
6. Network failure or validation failure: exit 1 with a one-line stderr reason; no partial
   files survive (write to temp, `mv` at the end, `trap` cleanup).
