## Defects to fix

1. **Crews diff is silently empty.** `_load_crews_ladders` tests `isinstance(ladder, list)`,
   but the catalog's `Crew.escalation_ladder` is `tuple[str, ...] | None`
   (`staffing/catalog.py`), so both real crews with ladders (`sol-low-glm-pi`, `luna-sol`)
   are dropped. Accept any non-string sequence. Also stop swallowing catalog errors: on
   `StaffingCatalogError`/`OSError`/`UnicodeError` return a single
   `{"source": "crews.yaml", "error": "<reason>"}` entry (mirror the benchmark path's error
   entry) and make `render_ladder_diff` print it as `ERROR:` — never an empty section.

2. **Role join never matches the real benchmark file.** Derived class keys use the router
   roles `impl | plan | review | judge | prose`; the benchmark's `role_aliases` maps
   benchmark-side names (`implementation`, `reviewer`, ...) to its canonical roles
   (`coder`, `planner`, `code-review`) and has no entry for `impl`, so every `by_role`
   lookup misses. The existing tests only pass because their fixtures fake
   `role_aliases: {"impl": "coder"}`. Add a module constant
   `ROUTER_ROLE_TO_BENCHMARK_ROLE = {"impl": "coder", "plan": "planner", "review": "code-review"}`
   (cite contract §3 in its docstring), apply it before `role_aliases` normalisation,
   and treat `judge`/`prose` classes as "no benchmark ladder for this role" (reported once in
   the JSON output as `unmatched_roles`, not silently dropped). Remove the fake alias from
   every fixture; the fixtures must use the real file's alias shape. Add one test that loads
   the real `ai-workforce-benchmark/config/escalation-ladders.json` (resolve it relative to
   this repo's parent directory; `pytest.skip` if absent) and asserts a derived
   `impl/.../python` class joins `coder-default`.

3. **Insufficient evidence is mislabelled as disagreement.** Today every benchmark ladder
   prints `✗ DISAGREES` with "derived ladder has no more rungs" because every class is
   `insufficient evidence, hand ladder retained`. That is wrong: the sprint-plan gate says
   the hand ladder is retained in that case. When no derived class for a ladder's role has
   `evidence_status == "derived"`, the entry must be `agreement: None`,
   `status: "insufficient evidence, hand ladder retained"`, carrying `classes_considered`
   (list of class_key) and `minimum_sample_size` (import `MINIMUM_SAMPLE_SIZE` from
   `rollup`, do not restate 5). Render it as
   `– <ladder_id> (<role>): insufficient evidence, hand ladder retained (<k> classes observed, none at n>=<N>)`.
   Same rule for crews: when no derived class has rungs, the crew entry gets the same
   `agreement: None` / status shape, never "has no overlap with any derived class".

4. **Diff per class, not pooled across classes.** `diff_against_benchmark` currently
   concatenates rungs from every class of a role into one list and diffs that. Contract §3
   and the packet say "per class or crew". For each derived class with
   `evidence_status == "derived"`, emit one diff entry against the role's ladder carrying
   `class_key`; a ladder with several derived classes yields several entries. Update
   `render_ladder_diff` to show `<ladder_id> (<role>) vs class <class_key>`.
