- Context: the independent reviewer reproduced that `_reviewer_fallbacks` counts any
  review/judge attempt whose `selection.excluded` contains an `independence` exclusion as a
  fallback. That is wrong: an independence exclusion shows independence was *enforced*, not
  that the router *fell back*. Example `router-run-da3c1a55b92c4b83849a445f3aed60d5`: basis
  `explicit`, reason says the selected route "is eligible", DeepSeek routes excluded for
  independence — reported as a fallback today. The P5-1 packet (line 74) says: when the
  selection data cannot decide a fallback truthfully, report the column as `unavailable`
  with the reason — never guess.

## The truthful rule (implement exactly this)

For each review/judge-role record with a `selection` mapping:

- `basis == "explicit"` → **not** a fallback (the caller chose the route; exclusions are
  enforcement). Certain.
- `basis == "explain_cheapest_eligible"` → the router took the first eligible route in
  marginal-price order. A fallback happened only if a route excluded for `independence`
  would have preceded the selected route in that order. `selection.excluded` records
  `{route_id, reason}` with no order or price, and the contract forbids re-running
  eligibility. Therefore: if `excluded` has **no** independence entry → not a fallback,
  certain; if it **has** one → **undecidable** from the record.
- any other basis, or no `selection` → undecidable.

Group output: replace the current list-of-fallbacks semantics with
`reviewer_fallbacks: {"count": <certain fallbacks, an int>, "undecidable": <int>,
"unavailable_reason": <str or null>}` where `unavailable_reason` is
`"selection.excluded records independence exclusions without explain order; fallback cannot be read from the record"`
when `undecidable > 0`, else null. Keep the JSON key name `reviewer_fallbacks`. Text
renderer: `reviewer_fallbacks: 0` when count is 0 and undecidable is 0;
`reviewer_fallbacks: <count> (+<undecidable> undecidable: <unavailable_reason>)` otherwise.
Do not change `_count_escalations` or any other column. Keep the module docstring for
`_reviewer_fallbacks` accurate.
